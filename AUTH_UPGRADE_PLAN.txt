Future Improvement: Move Admin Authentication from .env to MySQL

Current Setup: The current system uses environment variables (.env) to
store admin credentials. This approach is simple but has limitations: -
Only one admin account - Password stored as plain text - No password
recovery system - Not scalable

Improved Approach: Store admin accounts in a MySQL database.

Step 1: Create admins table

CREATE TABLE admins ( id INT AUTO_INCREMENT PRIMARY KEY, username
VARCHAR(50) NOT NULL UNIQUE, email VARCHAR(100) NOT NULL UNIQUE,
password_hash VARCHAR(255) NOT NULL, otp_code VARCHAR(10),
otp_expires_at DATETIME, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

Step 2: Hash passwords using bcrypt

npm install bcrypt

Example: const bcrypt = require(“bcrypt”); const hashedPassword = await
bcrypt.hash(“MyPassword123”, 10);

Step 3: Update login logic

-   Find admin by username
-   Compare password using bcrypt.compare()

Step 4: Forgot Password (Future)

Flow: 1. Admin enters email 2. System generates OTP 3. Save OTP + expiry
in DB 4. Send OTP via email 5. Admin enters OTP + new password 6. System
validates and updates password

Step 5: Send email (Nodemailer)

npm install nodemailer

Step 6: Reset password

-   Validate OTP
-   Hash new password
-   Update DB
-   Clear OTP fields

Benefits: - Secure password storage - Supports multiple admins - Enables
OTP and password reset - Scalable and production-ready

Note: .env is still used for development simplicity, but database-based
authentication is recommended for future upgrades.
